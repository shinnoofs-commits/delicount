# デリサポーター (DeliSupporter) 連携コンテキスト・仕様書

本プロジェクト（デリカウント / SwiftPOS / 値引き廃棄アプリ）は、発注・製造管理システム「デリサポーター (DeliSupporter / `C:\Users\user\移行データ`)」と実績データ連携および発注スケジュールが統合されています。
開発・運用・分析画面の改修を行う際は、以下の仕様と運用ルールを必ず前提としてください。

---

## 1. システム連携の概要

* **連携目的**:
  デリカウント側で収集・集計される日々の「スマレジ売上数」および「値引き・廃棄登録数」から**「製造実績数（売上数 ＋ 廃棄数）」**を算出し、デリサポーターの製造計画コレクション（`productionOverrides`）へ自動送信します。
* **データ送信タイミング**:
  毎日 22:10 JST（営業終了・廃棄登録完了後、Cloud Scheduler により自動同期）
* **データ送信先 (DeliSupporter)**:
  * Cloud Functions: `https://asia-northeast1-[PROJECT_ID].cloudfunctions.net/syncProductionActuals`
  * Next.js API Proxy: `http://localhost:3000/api/sync/production` (ローカル)
  * 認証ヘッダー: `x-api-key: delicount-sync-secret-2026` (環境変数 `SYNC_API_KEY`)

---

## 2. 送信データフォーマット

```json
{
  "storeId": "hon-atsugi",
  "targetDate": "YYYY-MM-DD",
  "items": [
    {
      "productId": "rec001",
      "productCode": "101",
      "productName": "商品名",
      "salesQty": 25,
      "wasteQty": 2,
      "productionQty": 27
    }
  ]
}
```

* **商品コード正規化**:
  デリサポーター側のマスタ（`masterProducts`）は先頭ゼロを除去した形式（`0101` → `101`）で管理されているため、送信時にも先頭ゼロを除去したコードを使用します。

---

## 3. 廃棄クロス分析（`/abc-analysis`）の集計ルール

* **商品名統合ロジック**:
  過去のPOSデータや廃棄データにおいて、商品IDや商品コードに表記揺れや変更履歴がある場合でも、**正規化された同一商品名（全角半角スペース除去、全角括弧正規化、小文字化）**のアイテムは1行に統合して集計・表示します。
* **値引販売指標の表示仕様**:
  廃棄クロス分析画面およびCSV出力では、値引き販売率（`%`）とともに必ず**「値引販売個数」**を表示・出力します。

---

## 4. 仕入先納品日設定と週3回発注スケジュール

* **スミダパッケージ・オカベの納品曜日**:
  **「火曜・木曜・土曜」** (納品不可日: `[0, 1, 3, 5]` = 日・月・水・金)
* **運用発注サイクル（週3回入力）**:
  1. **金曜 22:10**: 【翌週 火曜・水曜 製造分】を入力 → **火曜日 納品**（スミダ締切: 日曜15:30 / オカベ: 月曜14:00）
  2. **日曜 22:10**: 【翌週 木曜・金曜 製造分】を入力 → **木曜日 納品**（スミダ締切: 火曜15:30 / オカベ: 水曜14:00）
  3. **火曜 22:10**: 【今週末 土曜・日曜・翌週月曜 製造分】を入力 → **土曜日 納品**（スミダ締切: 木曜15:30 / オカベ: 金曜14:00）
* **自動計算ロジック**:
  デリサポーター側では `calculateDeliveryDate` により「当日使用する分は納品可能な直前の納品日」に自動集約されるため、デリカウントから実績が連携され次第、自動的に最新の発注数が再計算されます。
